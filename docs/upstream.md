## Module provenance

| New module | Origin | Notes |
|---|---|---|
| `src-tauri/src/capcut/` | Ported from `vendor/capcut-mate/src/pyJianYingDraft/` (`script_file.py`, `track.py`, `segment.py`, `video_segment.py`, `audio_segment.py`, `text_segment.py`, `effect_segment.py`, `animation.py`, `keyframe.py`, `local_materials.py`, `time_util.py`) | Direct structural port to Rust, µs timebase preserved as-is. Apache-2.0 attribution required: keep `NOTICE` text (Gary Guan 2024, Hommy 2026 modifications) in `THIRD_PARTY_NOTICES.md` and document changes made during the port. |
| `src-tauri/src/media/probe.rs` (Phase 3) | Reimplemented from `vendor/autocut/src-tauri/src/probe.rs` | Direct ffprobe JSON parsing approach (not capcut-mate's `pymediainfo`), per audit §4. Permission granted for direct reuse — port literally where practical, rewritten to i64-µs where autocut used f64 seconds; `fps` kept as an exact `Rational` rather than resolved to `f64` (autocut's own field), matching this project's timebase decision more strictly than a literal port would. Extended beyond autocut's `MediaInfo` with `codec`/`bitrate`/`audio_channels`/`sample_rate`/`rotation_deg`/`created_at` to match the `media[]` schema in `docs/project-format.md` (fields autocut's probe never needed). |
| `src-tauri/src/ffmpeg/binaries.rs` (Phase 3) | Adapted from `vendor/autocut/src-tauri/src/binaries.rs` | Layered sidecar path search and `#[cfg]` target-triple matrix (Windows x64 MSVC+GNU) carried over near-verbatim. Added a dev/test-only system-`PATH` fallback (`which`/`where`) not present in autocut, so this crate's tests run against the remote build server's apt-installed ffmpeg without any bundled binary — never consulted in a release build. Binary provenance/checksum decision itself (audit §6 risk #7, master prompt §59) remains deferred to Phase 12, not inherited from autocut's BtbN-pinned approach. |
| `src-tauri/src/ffmpeg/command.rs` (Phase 3) | New | Process-argument-array builder (`FfmpegArgs`) and `-progress pipe:1` parser/runner. Not present in autocut in this form (autocut builds `Command` args ad hoc per call site); written fresh to satisfy master prompt §66's "create FFmpeg command builders" instruction and to underlie probe/thumbnail/proxy/PCM extraction (and, later, Phase 6 rendering) through one code path. |
| `src-tauri/src/audio/pcm.rs` (Phase 3) | Ported from `vendor/autocut/src-tauri/src/audio.rs` | Incremental i16 PCM extraction (bounded-memory streaming read, odd-byte carry across reads) ported essentially as-is — no timebase rewrite needed, since this module only ever handled raw sample counts, not durations. Adapted to route through `crate::ffmpeg`/return `MediaError` instead of `anyhow::Error`. |
| `src-tauri/src/audio/waveform.rs` (Phase 3) | Ported from `vendor/autocut/src-tauri/src/waveform.rs` | Peak-per-bin downsampler ported as-is (no timebase to rewrite here either — autocut's version returns bare amplitudes with no timestamps). Extended with `WaveformResult::bin_duration_us`, computed from the real sample rate, since this project's canonical i64-µs timebase makes it cheap and worthwhile to hand callers instead of leaving bin→time mapping entirely up to the frontend as autocut does. |
| `src-tauri/src/media/thumbnail.rs`, `proxy.rs`, `import.rs` (Phase 3) | New | Thumbnail extraction (single-frame ffmpeg call), proxy generation (720p editing proxy, Off/Auto/Always modes, master prompt §8) with real `-progress`-driven Tauri events, and import-time format classification/folder scanning (master prompt §7). Neither upstream repo has a proxy-generation or thumbnail-generation module to draw from. |
| `src-tauri/src/db/mod.rs` (Phase 3) | New | SQLite media-library index (`rusqlite`, bundled/statically-linked sqlite3) per master prompt §35, kept separate from `project.json` as that section instructs. Schema/queries are original; no upstream equivalent (capcut-mate has no local media index, autocut has no persistence at all). |
| `src-tauri/src/commands/media.rs` (Phase 3) | New | Tauri command surface (import/probe/proxy/waveform/search) fronting the modules above, plus the `media:proxy-progress` event plumbing. Original to this project. |
| `src/stores/media.svelte.ts`, `src/components/media/MediaLibrary.svelte`, `src/components/preview/VideoPlayer.svelte` (Phase 3) | New (pattern informed by autocut) | Svelte 5 runes class-store pattern (`$state` fields directly on a class instance) informed by `vendor/autocut/src/lib/store.svelte.ts`'s design (audit §2), reimplemented for this project's media-library/preview state rather than copied — the state shape and IPC surface are entirely different (autocut has no library, no SQLite, no proxy concept). `MediaLibrary.svelte`'s native drag-and-drop (`getCurrentWebview().onDragDropEvent`) and `VideoPlayer.svelte`'s `asset:`-protocol playback follow the same Tauri APIs autocut's `Dropzone`/`VideoPlayer` components use, but the components themselves are original. |
| `src-tauri/src/vad/` | Reimplemented from `vendor/autocut/src-tauri/src/vad.rs` | Two-phase score/segment design, `voice_activity_detector` crate (Silero V5) reused as a direct dependency (independently licensed on crates.io regardless of autocut's own status). Rewritten f64s → i64us. |
| `src-tauri/src/render/export_mp4` (Phase 6) | Reimplemented from `vendor/autocut/src-tauri/src/export_mp4.rs` | Concat-demuxer + inpoint/outpoint technique, extended to multi-track compositing (autocut's version is single-source only). |
